## 1. Project Overview

**What:** Modular business management suite (Odoo-inspired) for a single Indian business.
**Users:** 1–10 users, single tenant. Roles (seeded in `schema.sql`): `admin`, `accounts`, `sales`, `inventory`, `readonly` — each with a per-module `can_read/write/submit/cancel` matrix in `role_permissions`.
**Stack:** React · Node.js/Express · TypeScript · PostgreSQL 16 · Docker Compose (deploy).
**Architecture:** Strict modular monolith. Modules: `core`, `crm`, `sales`, `invoicing`, `accounting`, `inventory`. Each module owns its tables and exposes service interfaces. Cross-module work runs in a single PostgreSQL transaction; domain events handle post-commit side effects.
**Process:** Every phase runs the gstack loop:
`/office-hours` → `/plan-ceo-review` + `/plan-eng-review` → build (Claude Code, mentor mode) → `/review` → `/qa` → `/ship` → `/document-release` → `/retro`

**Starting point:** Existing validated scaffold — PostgreSQL schema (constraints, triggers, seed data), document engine, accounting/inventory/invoicing services, 25-assertion integration suite + concurrency test, `CLAUDE.md` with architectural rules.

---

## 2. Non-Negotiable Invariants (enforced app-level AND db-level)

- Append-only ledgers. Corrections via reversals only — both entries stay posted and net to zero.
- Journal flow: draft → lines → posted (required by trigger architecture).
- Deferred constraint triggers verify journal balance.
- Integer paise everywhere. No floats near money.
- Stock concurrency: ordered `SELECT ... FOR UPDATE`.
- Audit trail: every posting, invoice, and stock move records `created_by` and timestamp.
- No cross-module table access — service interfaces only.
